🧪 OAuth POC Test

⚠️ Important Setup Required:
  1. Go to Dropbox Sign OAuth App Registration
  2. Create a new OAuth application
  3. Set redirect URI to: http://localhost:3001/oauth/callback
  4. Copy your Client ID and Client Secret
  5. Add them to your .env file as OAUTH_CLIENT_ID and OAUTH_CLIENT_SECRET
  6. Restart your server

Step 1: Connect with OAuth

Use different IDs to test multiple OAuth connections
What happens when you click "Connect with Dropbox Sign OAuth":
  1. You'll be redirected to Dropbox Sign
  2. Log in as the user you want to test (e.g., dbx.microsoft@gmail.com)
  3. Authorize the application
  4. You'll be redirected back with access token
  5. Token is stored in memory (POC only)

Step 2: Send Signature Request with OAuth

⚠️ Important: "Acting on behalf of" cannot be removed

After extensive testing, we confirmed that Dropbox Sign OAuth always shows "acting on behalf of" in audit trails when using an API App. This is by design for legal accountability.

Choose Sending Method:

Note: Both methods show "acting on behalf of" in audit trails.

Send with Uploaded Document

🧪 Alternative: Unclaimed Draft (Self-Claim)

Create an unclaimed draft as the OAuth user, then have them claim it themselves. This might avoid "acting on behalf of".

Send with Template

This will send a signature request using the OAuth access token for the connected user. The audit trail should show ONLY that user's email - no "acting on behalf of".
Check your template to see what roles it has. Common roles: Client, Signer, Employee, Contractor
⚠️ To remove "acting on behalf of": Leave this UNCHECKED and empty!
